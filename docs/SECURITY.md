# Security design

Passwords are bcrypt-hashed at cost 12. Sessions use 256-bit random opaque cookie tokens; only SHA-256 digests and separate random CSRF tokens are stored in PostgreSQL. Cookies are HttpOnly, SameSite=Lax, and Secure in production. Session expiry defaults to seven days, at most 30. Logout deletes the current session; resetting a password revokes all account sessions. Password resets use digested, expiring, single-use 30-minute tokens and require SMTP.

Every private handler scopes reads and writes to the authenticated user. Component assignments verify monitor ownership. Public status pages return only chosen component names, statuses, timestamps, observed daily uptime, and sanitized incident times/statuses. They never return monitor URLs, owners, email addresses, credentials, check error messages, or delivery details. Unpublished pages return 404.

Writes require an exact configured Origin. Authenticated writes also require X-CSRF-Token from /auth/me. Credentialed CORS permits only APP_ORIGIN. Production requires HTTPS and rejects the development mock exception. Configure one trusted reverse proxy; prevent direct public access to the API so forwarded headers cannot be forged. ASGI security headers, 32 KiB body limits, safe errors, and structured Python logging avoid body, session, and credential logging. Rate limits apply globally and to sensitive authentication endpoints; current limit counters are per API instance. For multiple API replicas, enforce shared limits at the trusted ingress.

HTTP checks permit only HTTP/HTTPS without credentials or fragments. Production permits standard ports 80/443 only. Each check resolves all addresses, rejects any answer containing private, loopback, link-local, multicast, carrier-grade NAT, reserved, or metadata ranges, and pins the validated selected IP into the socket lookup. The original hostname remains for Host, TLS SNI, and certificate verification. Redirects are never followed. DNS and HTTP share one bounded deadline. Requests have no reused sockets and response bodies are immediately destroyed. Tests cover mixed DNS answers, IPv4-mapped IPv6, pinned socket lookups, disabled redirects, timeouts, and unsafe ports. The local mock bypass allows only an exact loopback origin in nonproduction and cannot be user-configured through the API.

Use network egress rules in production to deny private/reserved ranges and cloud metadata, including at the VPC/container/firewall layer. Keep PostgreSQL private, enforce least-privilege roles, use TLS to remote PostgreSQL and SMTP, and separate migration credentials from the runtime role. Provision secrets through the deployment platform; never commit .env. The included local password is a development placeholder.

Notification outbox events have unique incident/channel/event keys. Claims are leased and fenced, delivery attempts have bounded SMTP timeouts, and failures back off. SMTP does not offer atomic commit with PostgreSQL: a process crash after provider acceptance but before marking delivered can cause redelivery. Stable Message-ID helps deduplication but exactly-once mailbox delivery is not guaranteed. Do not interpret pending or sending as delivered.

Run `npm.cmd audit` and `npm.cmd audit --omit=dev` regularly; review updates and run all checks before deployment. Run `npm.cmd run audit:python` for Python dependencies too. Keep Python, frontend Node, PostgreSQL, Nginx, Docker images and dependencies patched. See PROGRESS.md for actual verification and remaining operational limitations.
